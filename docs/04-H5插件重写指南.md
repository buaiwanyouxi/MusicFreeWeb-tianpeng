# H5 插件重写指南

## 一、核心发现：现有插件可能无需重写

经过深入分析 `zyb/musicfree-h5` 基座项目，发现其内置了 `adaptMusicFreePlugin()` 适配器，可以自动将 MusicFree 原生插件格式转换为 H5 格式。

### 适配映射关系

| 原生方法 | H5 方法 |
|---------|---------|
| `search(query, page, type)` | `searchSongs(query, page)` |
| `getMediaSource(musicItem, quality)` | `resolveStream(track)` |
| `getTopLists()` | `getTopLists()` |
| `getTopListDetail(item, page)` | `getTopListDetail(playlist)` |
| `getMusicSheetInfo(sheet, page)` | `getPlaylistSongs(playlist)` |
| `getRecommendSheetTags()` | `getRecommendSheetTags()` |
| `getRecommendSheetsByTag(tag, page)` | `getRecommendSheetsByTag(tag, page)` |

### 前提条件

插件只要满足以下条件即可被自动适配：
1. 使用 `module.exports` 导出对象
2. 对象包含 `platform` 字段
3. 对象包含 `search` 方法（或其他核心方法）

## 三、插件格式模板

### 格式 A：原生 MusicFree 格式（推荐，零改动）

```js
'use strict';
module.exports = {
  platform: 'xxx',
  version: '1.0.0',
  author: 'author',
  description: '描述',
  
  async search(query, page, type) {
    const axios = require('axios');
    const resp = await axios.get('https://api.example.com/search', {
      params: { keyword: query, page }
    });
    return {
      isEnd: true,
      data: resp.data.result.map(item => ({
        id: item.id,
        platform: 'xxx',
        title: item.title,
        artist: item.artist,
        artwork: item.cover,
        duration: item.duration,
      }))
    };
  },
  
  async getMediaSource(musicItem, quality) {
    const axios = require('axios');
    const resp = await axios.get(`https://api.example.com/play/${musicItem.id}`);
    return { url: resp.data.url };
  }
};
```

### 格式 B：H5 原生格式（如需完全控制）

```js
;(function() {
  const plugin = {
    name: 'xxx',
    version: '1.0.0',
    author: 'author',
    capabilities: ['search', 'stream', 'lyrics'],
    
    async searchSongs(query, page) {
      const resp = await MusicFreeH5.fetch('https://api.example.com/search', {
        method: 'POST',
        body: JSON.stringify({ keyword: query, page: page || 1 })
      });
      const data = await resp.json();
      return {
        items: data.result.map(item => ({
          id: item.id,
          title: item.title,
          artist: item.artist,
          artwork: item.cover,
          platform: 'xxx',
        })),
        hasMore: data.has_more
      };
    },
    
    async resolveStream(track) {
      const resp = await MusicFreeH5.fetch(`https://api.example.com/play/${track.id}`);
      const data = await resp.json();
      return { url: data.url };
    }
  };
  
  if (typeof MusicFreeH5 !== 'undefined' && MusicFreeH5.registerPlugin) {
    MusicFreeH5.registerPlugin(() => plugin);
  }
})();
```

## 四、从移动端迁移的检查清单

### 4.1 必须检查

- [ ] `module.exports` 导出格式是否正确
- [ ] `platform` 字段是否设置
- [ ] `require('axios')` 是否能正常工作（通过 requireShim）
- [ ] API 域名是否在代理白名单中

### 4.2 可能需要调整

- [ ] Cookie 管理：浏览器环境无法直接设置 `Set-Cookie`
- [ ] `response.headers['set-cookie']`：代理可能不返回此头
- [ ] 特殊请求头：某些 API 需要特定 Referer/UA
- [ ] 响应拦截：axios 响应拦截器在 shim 中可能行为不同

### 4.3 不需要改动

- [ ] cheerio HTML 解析 → requireShim 已提供
- [ ] crypto-js 加密 → requireShim 已提供
- [ ] 纯 JS 实现的 MD5/签名 → 直接可用
- [ ] 数据结构定义 → 自动适配

## 五、代理配置

### 添加新 API 域名

如果插件使用的 API 域名不在代理白名单中，需要修改两个文件：

#### 1. `src/lib/pluginHost.ts` — URL 重写规则

```ts
const urlRewriteRules: Record<string, string> = {
  // 已有规则...
  'api.example.com': '/api/proxy/example/',
};
```

#### 2. `netlify/functions/proxy.js` — 代理白名单

```js
const ALLOWED_HOSTS = {
  // 已有规则...
  'example_api': 'https://api.example.com',
};
```

### 代理请求流程

```
插件代码 → axios.get('https://api.example.com/search')
         → requireShim 拦截 → rewriteUrl()
         → fetch('/api/proxy/example/search')
         → Netlify Function proxy.js
         → https://api.example.com/search（真实请求）
         → 返回响应（带 CORS 头）
```

## 七、常见问题

### Q: 插件加载报错 "Cannot find module 'xxx'"
A: 检查 requireShim 是否提供了该模块。如果是新依赖，需要在 pluginHost.ts 的 `createRequireShim` 中添加。

### Q: API 请求 403/401
A: 检查代理是否正确转发请求头。某些 API 需要特定的 Referer/UA/Cookie。

### Q: 播放无声音
A: 检查 getMediaSource/resolveStream 返回的 URL 是否可访问。B站 m4s 格式需要 MSE 播放器。

### Q: 搜索结果为空
A: 检查 API 响应格式是否匹配。使用 adaptMusicFreePlugin 时，确保返回的数据结构符合 ISearchResult。

### Q: Cookie 无法保持
A: 浏览器环境无法像 Node.js 一样管理 Cookie。需要在请求中手动携带 Cookie（通过 headers）。
