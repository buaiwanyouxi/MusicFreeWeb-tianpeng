## 二、6 个插件详细分析

### 2.1 哔哩哔哩（bilibili.plugin.js）

| 属性 | 值 |
|------|-----|
| 版本 | 1.1.5 |
| 依赖 | axios + 内置纯 JS MD5 |
| 特殊 | SESSDATA Cookie、WBI 签名、buvid 请求 |

**实现方法**：search、getMediaSource、getMusicInfo、getTopLists、getTopListDetail、getMusicSheetInfo、importVideo、importMusicSheet

**H5 适配难度**：★★★☆☆（中等）
- 内置 MD5 可直接使用
- axios 通过 requireShim 提供
- WBI 签名逻辑可移植
- SESSDATA 通过 userVariables 配置
- B站 API 已在代理白名单中

---

### 2.2 我要下歌（xiage.js）

| 属性 | 值 |
|------|-----|
| 版本 | 0.0.14 |
| 依赖 | axios + qs（可选） |
| 特殊 | 无认证需求，多源路由 |

**实现方法**：search、getMediaSource、getLyric、getTopLists、getTopListDetail、getMusicSheetInfo、importMusicSheet、importMusicItem

**H5 适配难度**：★★☆☆☆（较低）
- 无加密依赖
- 使用 Tonzhon API 搜索
- 多源播放（网易云/腾讯/酷狗）
- 需确认 Tonzhon API 是否在代理白名单

---

### 2.3 布谷音乐（buguyy.js）

| 属性 | 值 |
|------|-----|
| 版本 | 0.0.5 |
| 依赖 | axios + **cheerio** |
| 特殊 | HTML 解析、跨源解析、Laravel 加密 |

**实现方法**：search、getMediaSource、getLyric、getMusicInfo、getTopLists、getTopListDetail、getRecommendSheetTags、getRecommendSheetsByTag、getMusicSheetInfo

**H5 适配难度**：★★★★☆（较高）
- cheerio 在 requireShim 中已提供
- HTML 解析逻辑复杂（网易云 SSR、酷我 Nuxt、酷狗 SSR）
- 跨源解析（crossResolve）需额外 API 调用
- 酷我榜单需要特殊 headers（`kuwoApiGet`）
- 歌词三级链回退（酷我 → 布谷镜像 → followlyrics.com）

---

### 2.4 咪咕音乐（migu.js）

| 属性 | 值 |
|------|-----|
| 版本 | 0.0.3 |
| 依赖 | axios |
| 特殊 | miguCookie（榜单用）、Device ID |

**实现方法**：search、getMediaSource、getLyric、getTopLists、getTopListDetail

**H5 适配难度**：★★☆☆☆（较低）
- 无 cheerio/crypto 依赖
- H5 平台 headers 已内置
- 咪咕 API 已在代理白名单中
- Cookie 通过 userVariables 配置

---

### 2.5 歌曲宝（gequbao.js）

| 属性 | 值 |
|------|-----|
| 版本 | 1.0.0 |
| 依赖 | axios |
| 特殊 | Session Cookie + play_id 两步流程 |

**实现方法**：search、getMediaSource、getLyric、getTopLists、getTopListDetail、getMusicSheetInfo、importMusicItem、importMusicSheet

**H5 适配难度**：★★★☆☆（中等）
- Cookie 管理需跨请求保持
- HTML 解析用正则（无 cheerio 依赖）
- 两步请求：GET 页面 → POST 获取播放地址
- 需确认 gequbao.com 是否在代理白名单

---

### 2.6 放屁音乐网（fangpi.js）

| 属性 | 值 |
|------|-----|
| 版本 | 1.0.0 |
| 依赖 | axios |
| 特殊 | 与 gequbao 逻辑完全相同 |

**实现方法**：与 gequbao 完全一致

**H5 适配难度**：★★★☆☆（中等）
- 仅 BASE URL 和 PLATFORM 与 gequbao 不同
- 可与 gequbao 共享适配代码
- 需确认 fangpi.com 是否在代理白名单

## 三、依赖汇总

| 依赖 | 使用插件 | requireShim 提供 |
|------|---------|-----------------|
| axios | 全部 6 个 | ✅ 已提供 |
| cheerio | buguyy | ✅ 已提供 |
| crypto-js | 无（bilibili 用内置 MD5） | ✅ 已提供 |
| qs | xiage（可选） | ✅ 已提供 |
| dayjs | 无 | ✅ 已提供 |
| he | 无 | ✅ 已提供 |
| big-integer | 无 | ✅ 已提供 |

**结论：所有插件的依赖均已由 H5 基座的 requireShim 覆盖。**

## 五、适配策略总结

| 插件 | 策略 | 需改动 |
|------|------|--------|
| bilibili | 直接使用（adaptMusicFreePlugin 适配） | 可能需微调 WBI 签名中的请求方式 |
| xiage | 直接使用 | 确认 Tonzhon API 代理 |
| buguyy | 直接使用 | cheerio 已由 requireShim 提供 |
| migu | 直接使用 | 最简单，几乎无需改动 |
| gequbao | 直接使用 + 添加代理 | 需在 proxy.js 添加 gequbao.com |
| fangpi | 直接使用 + 添加代理 | 需在 proxy.js 添加 fangpi.com |

**核心结论：6 个插件均有可能零改动直接在 H5 基座中运行，只需确保代理覆盖。**
